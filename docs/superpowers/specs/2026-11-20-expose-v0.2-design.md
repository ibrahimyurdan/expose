# expose v0.2 design: champ select scouting, ready to publish

date: 2026-11-20. status: approved direction from the owner ("both layouts look good, merge them; make it really professional, like a real app we are going to publish"; ranked matching and stats on by default, no warning screen).

## why

players lose lp and an hour to troll lobbies. the tell is usually visible before the game starts: a teammate autofilled, on a loss streak, first-timing a champion, with a bad kda, or on what looks like a bought account. expose should put that on one screen during champ select so the player can decide to dodge in time. today expose only lists teammate names in ranked and opens op.gg.

## goals

- one clean champ select screen that shows, per teammate: who they are, their slot (alias, role, champion), rank, recent results, kda, experience on the current champion, and red flags, with a one-line team summary and the dodge button.
- in ranked solo/duo, match each revealed name to its slot (the "gromp", "murk wolf" aliases) exactly when possible and clearly marked as a guess otherwise.
- the same screen in normal and draft games, where nothing is hidden.
- an app that feels publishable: its own visual identity (not the old gold hextech look and not a copy of reveal), first-run welcome, clear idle and error states, organized settings, remembered window size and position.
- keep auto-accept and the safe two-click dodge; add an armed last-second dodge.

## non-goals

- enemy team identities (riot zeroes them; out of scope since v0.1).
- in-game overlays, draft or matchup analytics, win probability.
- auto-dodging based on flags. dodging always starts with the player (the last-second dodge is armed by the player per lobby).
- a riot api key or any server of our own. everything comes from the local league and riot clients.

## anti-goals

- never show a slot match as certain when it is a guess.
- never reveal a teammate that the riot client itself does not expose (for example a player using riot's "hide my name" streamer mode). matches are only accepted against names the riot client already lists.
- no slow screen: identities and slot info appear immediately, stats fill in as they arrive.

## what the user sees

window: about 460 x 680, resizable down to 420 x 600, remembers size and position. dark, neutral graphite surfaces, one accent color, semantic red/amber/green only for flags and results. system font (segoe ui variable on windows, sf pro on macos) with tabular numbers.

- **waiting**: league is not running. a calm empty state ("open league of legends and expose connects on its own"), connection pill in the header.
- **idle**: connected, not in champ select. auto-accept toggle front and center, a short "what happens next" line, last lobby summary if any.
- **lobby** (champ select), the merged layout:
  - top: phase and countdown, then a summary bar: "4 red flags on 2 teammates" (or "no red flags"), the dodge button (arm, then confirm) and a "dodge at the last second" toggle.
  - one row per teammate, your own row included:
    - line 1: champion icon, slot name (alias in ranked, real name elsewhere), role, champion.
    - line 2: real name with a match badge (exact or likely), rank (tier color), last 10 results as dots, kda, games on this champion.
    - line 3: red flag chips (red for strong, amber for mild), or a quiet "looks fine".
  - click a row to expand: last 10 games (champion, k/d/a, result, how long ago), role split, account level and ranked games this season, an op.gg / u.gg button.
- **settings**: sections for general (launch at login, auto-accept), champ select (reveal and match in ranked, auto-open scout site, scout site), dodge (last-second lead time), about (version, update link, open logs folder).
- **first run**: a short welcome with the three things expose does and a "get started" button. no risk warning (owner's call).
- **notices**: brief toasts for failures (riot client unreachable, dodge failed), never raw error strings.

## matching identities in ranked solo/duo

inputs, all local:
- the league session `/lol-champ-select/v1/session`: per `myTeam` entry `cellId`, `assignedPosition`, `championId` / `championPickIntent`, `spell1Id` / `spell2Id`, `isAutofilled`, `nameVisibilityType` (VISIBLE, HIDDEN, UNHIDDEN), `puuid` (empty when hidden), `obfuscatedPuuid`, `gameName` / `tagLine` (empty when hidden); plus `localPlayerCellId` and `chatDetails.multiUserChatId`.
- the riot client `/chat/v5/participants`, filtered to the conversation whose `cid` contains the session's `multiUserChatId` (fallback: cid contains `champ-select`): real `puuid`, `game_name`, `game_tag`.

players are keyed by `obfuscatedPuuid` (or `puuid` when visible), never by `cellId`: pick-order swaps move players between cells.

resolution order, each step only touches players still unresolved:
1. **self**: the `localPlayerCellId` cell is you. exact.
2. **visible or unhidden**: entries with a real `puuid` (party members, non-anonymous queues). exact.
3. **scramble key**: riot derives each hidden `obfuscatedPuuid` from the real puuid with one 128-bit xor key per lobby (public research, three independent tools, nov 2026). expose recovers the key from the data instead of hardcoding it: for each candidate real puuid r, K = obfuscated[0] xor r; keep the K that maps the most hidden players into the riot client's participant set, and accept it only if it maps at least two players and no other K ties it. every accepted match is then an exact, verified match. players whose decoded puuid is not in the participant set stay unmatched.
4. **elimination**: if exactly one hidden player and one unmatched name remain, they match. exact.
5. **best guess**: for what is left, score each (slot, name) pair from the name's last 20 summoner's rift games: share of games in the slot's role (weight lowered when the slot is autofilled), share with the slot's exact summoner spell pair, games on the slot's champion plus mastery. try every assignment (at most 120) and keep the best. shown as "likely", with the assignment's lead over the runner-up as a confidence level (high, medium, low).

aliases are reproduced like the client does: `aliases[originalSlot % 20]`, where originalSlot is the player's position in the team (sorted by cell) the first time expose saw them in this lobby, and the 20 names are, in order: Gromp, Krug, Murk Wolf, Raptor, Scuttle Crab, Minion, Void Grub, Sentinel, Brambleback, Wraith, Poro, Spiderling, Meep, Stellacorn, Sprite, Silverwing, Drake-Hound, Basilisk, Tuskbeast, Wyvern (from the 16.23 client's MY_TEAM_HIDDEN_NAME_KEYS and its en_us strings).

the log records, per lobby, which step matched each player (never the puuids), so a real ranked game verifies the scramble-key step.

## stats and red flags

per player puuid, fetched in parallel (at most 4 requests at a time), cached for the session and for 10 minutes across lobbies:
- `/lol-summoner/v2/summoners/puuid/{puuid}`: level, riot id, icon.
- `/lol-ranked/v1/ranked-stats/{puuid}`: `RANKED_SOLO_5x5` tier, division, lp, wins, losses, provisional.
- `/lol-match-history/v1/products/lol/{puuid}/matches?begIndex=0&endIndex=19`: last 20 games. per game: queue, start time, duration, champion, win, k/d/a, lane and role, cs, spells. remakes (under 5 minutes) are ignored.
- `/lol-champion-mastery/v1/{puuid}/champion-mastery`: points and last play time per champion.

each fetch is independent: a missing piece hides only its own stat.

red flags (thresholds are the builder's call and live in one tested function):
- **autofilled** (red): the slot's `isAutofilled`, or with at least 8 sr games, the slot's role is not one of the player's two most played roles.
- **loss streak** (red at 3+, labelled "lost last N"): consecutive losses at the top of the history, ranked and normal sr games.
- **first time on champion** (red): no mastery points on the slot's champion; "new to champion" (amber) when under 10,000 points and no games in the last 20.
- **low win rate** (amber): under 40% across at least 10 recent sr games.
- **bad kda** (amber): average kda under 1.5 across the last 10 sr games.
- **on tilt** (amber): 5 or more games in the last 6 hours with more losses than wins.
- **fresh account** (amber): level under 60 while ranked gold or above ("possibly bought or boosted"). a games-played signal was dropped: early in a season everyone has few games, and the client does not report last season's count.
- **no data** (neutral): match history unavailable.

the summary counts red flags as 1 and amber as 0.5, rounded for display as "N red flags on M teammates" (red only), with amber shown as "M warnings" when there are no reds.

## dodge

- the two-click dodge stays (arm, confirm within 3 seconds).
- new: "dodge at the last second". when armed, expose dodges when the finalization timer reaches the lead time (default 1.5 s, adjustable 1 to 3 s in settings). disarms itself when the lobby changes or ends. shown with a visible countdown so it never surprises the player.

## app polish

- window: remember size and position (tauri-plugin-window-state), resizable with sensible minimums.
- tray (windows) and dock (macos) behave as in v0.1.
- the update check keeps showing an "update available" pill in the header that links to the release page. in-app auto-update needs a signing key stored as a github secret and is left for later.
- logs as in v0.1; settings has "open logs folder".

## architecture

backend (rust, `src-tauri/src`):
- `lobby/` (new): `session.rs` (richer champ select session model), `aliases.rs`, `identity.rs` (resolution steps 1 to 5, pure and unit tested), `flags.rs` (pure, unit tested), `stats.rs` (fetch and aggregate with cache and concurrency limit), `mod.rs` (builds the `Lobby` view model and emits it).
- `features/teammates.rs` is replaced by the lobby module; `features/dodge.rs` (new) owns the armed last-second dodge.
- one event `expose://lobby` carries the whole lobby view; it is re-emitted when identities resolve and as stats arrive. `get_lobby` returns the latest for a freshly mounted ui.

frontend (react, `src/`): a new small design system (tokens in `index.css`, components for button, toggle, chip, pill, card, tooltip), screens (`Waiting`, `Idle`, `Lobby`, `Settings`, `Welcome`), and the lobby components (`LobbySummary`, `PlayerRow`, `PlayerDetail`, `DodgeControl`). the old gold hextech components are retired.

## testing and verification

- rust unit tests: alias assignment and swaps, every identity step (including the xor recovery with synthetic data, ties, a missing participant, one hidden player), heuristic assignment, flag thresholds, match history aggregation from fixture json.
- frontend: typecheck and build; the lobby screen gets a dev-only fixture mode (a fake lobby) so the ui can be reviewed without league running.
- checks as in v0.1: fmt, clippy -D warnings, tests on macos and cross-checked for windows, ci builds the windows installer.
- live: one ranked game on the owner's pc confirms the scramble-key step from the log; one normal game confirms stats and flags.

## builder's calls

window size and visual direction; flag thresholds; cache lifetimes; the last-second dodge default lead time; keeping the update notice instead of an auto-updater; dropping the gold hextech theme; no chat-message correlation in v0.2 (the scramble key covers it).
