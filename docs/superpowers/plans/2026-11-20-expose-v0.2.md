# expose v0.2 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** turn expose into a publishable champ select scouting app: per-teammate stats and red flags, exact or clearly-guessed slot matching in ranked, an armed last-second dodge, and a new professional ui.

**Architecture:** a new rust `lobby` module turns each champ select session event into one `LobbyView` (identities, stats, flags, summary) that is emitted as `expose://lobby` and re-emitted as stats arrive. identity resolution, stats aggregation and flags are pure functions with unit tests; network calls go through `LcuClient`. the react frontend is rebuilt on a small token-based design system with five screens and a dev fixture mode that renders without league.

**Tech stack:** tauri 2.11, rust (tokio, serde, reqwest via the existing `LcuClient`), react 19 + typescript + vite 8 + tailwind 4, lucide-react icons, radix primitives already in the repo.

**Spec:** `docs/superpowers/specs/2026-11-20-expose-v0.2-design.md` (read it first; this plan argues from it).

## Review focus

1. a lobby where the riot client is not running or returns no participants: every hidden slot still shows its alias, role and champion; identities stay empty; no error loop. (task 6 test `view_without_participants_keeps_aliases`)
2. a pick-order swap mid champ select: a player's alias, identity and stats follow the player, not the cell. (task 1 test `alias_survives_cell_swap`, task 6 test `identity_follows_player_after_swap`)
3. a stats endpoint failing for one player (private or 404): that player shows "no match history", everyone else still loads. (task 3 test `partial_stats_when_history_fails`)
4. the app opened mid champ select, or a requeue into a new lobby: state resets on a new `gameId`; no names from the previous lobby leak in. (task 6 test `new_game_id_resets_lobby`)
5. last-second dodge armed, then the lobby ends or changes: no dodge fires afterwards. (task 7 test `disarms_on_new_game`)

### task 2: exact identity resolution

**Files:** create `lobby/identity.rs`.

**Interfaces – consumes:** task 1 `Session`, `SessionPlayer::key/is_hidden`. **produces:**
- `#[derive(Debug, Clone, PartialEq, Eq)] pub struct Candidate { pub puuid: String, pub game_name: String, pub tag_line: String }` (built by task 6 from riot client participants).
- `#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize)] #[serde(rename_all = "camelCase")] pub enum MatchKind { Own, Visible, Key, Elimination, Guess }`; same derives for `pub enum Confidence { High, Medium, Low }`.
- `#[derive(Debug, Clone, PartialEq, Eq)] pub struct Identity { pub puuid: String, pub game_name: String, pub tag_line: String, pub kind: MatchKind, pub confidence: Confidence }` – exact kinds always carry `High`.
- `pub fn parse_uuid(text: &str) -> Option<u128>` (accepts 8-4-4-4-12 hex, any case; rejects anything else) and `pub fn format_uuid(value: u128) -> String` (lowercase 8-4-4-4-12).
- `pub fn recover_key(hidden: &[u128], real: &[u128]) -> Option<u128>`.
- `pub fn resolve_exact(session: &Session, candidates: &[Candidate]) -> HashMap<String, Identity>` – keyed by player key.

algorithm for `recover_key` (the implementer cannot infer the acceptance rule):

```text
for every pair (h in hidden, r in real): k = h xor r
score(k) = count of h in hidden with (h xor k) in real
best = the k values with the highest score
accept only if best has exactly one distinct k and its score >= 2
```

`resolve_exact` steps, in order, each skipping players already resolved: own (cell == `local_player_cell_id`; name from the session, else from the candidate with the same puuid), visible (non-empty `puuid`; same name rule), key (hidden players with a parseable `obfuscated_puuid`, decoded with `recover_key` over the candidates' puuids; only decoded values present in the candidates are accepted), elimination (exactly one unresolved hidden player and exactly one candidate not yet used by any identity).

  - `parses_and_formats_uuids` – round trip; uppercase accepted; `"not-a-uuid"` and a 31-digit value rejected.
  - `recovers_the_shared_key` – four real puuids, hidden = real xor K for a random-looking K, plus one extra real puuid (yourself); `recover_key` returns K.
  - `rejects_a_single_hidden_player` – one hidden value; `None` (score 1 is not enough).
  - `tolerates_a_player_missing_from_chat` – four hidden, only three of their real puuids in `real`; returns K.
  - `rejects_ambiguous_keys` – construct two keys that each map exactly two hidden values into `real`; `None`.
  - `resolves_own_visible_key_and_elimination` – a session with you, one unhidden duo (real puuid in session), two hidden players decodable with K, and a fourth hidden player whose obfuscated puuid does not decode into the candidates while exactly one candidate is left: kinds are Own, Visible, Key, Key, Elimination.

### task 4: best-guess slot assignment

**Files:** modify `lobby/identity.rs`.

**Interfaces – consumes:** task 2 types, task 3 `Position`, `PlayerHistory`, `PlayerStats`. **produces:**
- `pub struct SlotHint { pub key: String, pub position: Option<Position>, pub is_autofilled: bool, pub spells: (i64, i64), pub champion_id: i64 }`.
- `pub fn guess(slots: &[SlotHint], candidates: &[(Candidate, PlayerStats)]) -> HashMap<String, Identity>` – every returned identity has kind `Guess`.

scoring (fixed by the spec): `score(slot, player) = w_role * role_share + 0.5 * spell_share + champion_signal`, where `w_role` is 1.0, or 0.25 when the slot is autofilled; `champion_signal` is 0 when the slot has no champion, else `0.7 * min(1, games_on / 5) + 0.3 * mastery_term` with `mastery_term` 1 at 10,000+ points, 0.5 above 0, 0 otherwise. try every assignment of candidates to slots (up to 5! = 120; if there are more candidates than slots, assign the best subset); total = sum of scores. confidence from the lead of the best total over the runner-up: ≥ 0.5 high, ≥ 0.2 medium, else low. a candidate without history can still be placed but contributes 0.
